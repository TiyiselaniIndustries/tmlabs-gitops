# tmlabs-gitops

Argo CD source of truth for the TmLabs test environment.

```
apps/                      Argo CD Applications (repo/path/namespace only — no secrets)
manifests/tmlabs/          Helm chart generated by `aspire publish` in tmlabs-backend (CI-owned)
manifests/tmlabs-extras/   Hand-maintained: Ingress + ExternalSecrets
```

## How it deploys

1. A push to `tmlabs-backend` (or `tmlabs-frontend`, which dispatches
   `frontend-changed`) runs the backend `deploy-test` workflow.
2. That workflow builds and pushes four images to the Zot registry, runs
   `aspire publish` to generate the Helm chart, pins the image tags, and — when
   `GITOPS_PUSH_ENABLED=true` — commits the chart here under `manifests/tmlabs`.
3. Argo CD notices the commit and syncs `tmlabs` and `tmlabs-extras`.

Do not edit `manifests/tmlabs` by hand; CI overwrites it. Change the AppHost or
the workflow instead.

## Bootstrap

```bash
kubectl apply -f apps/
kubectl get applications -n argocd
```

`apps/tmlabs-extras.yaml` should be synced before the first app deploy so that
`web-secrets`, `blogapi-secrets`, and `chatservice-secrets` exist when pods start.

Full runbook, including prerequisites and GitHub configuration:
`tmlabs-backend/docs/argocd-deployment.md`.
